    Two privacy tiers, enforced in code

    Everything that sees a patient note runs on this machine through Ollama. A cloud model is used only to parse public trial registry text into atomic criteria, and the type system stops patient data from reaching it (llm_public.py, checked by tests/test_privacy.py).

    Agents

    AgentTierWhat it does
    Patient profilerlocal LLMNote → structured profile; every fact grounded in a quoted span
    Criteria parsercloud API · public textEligibility text → atomic criteria with numeric checks (offline, ahead of time)
    Pre-filterrulesBM25 or hybrid relevance; age/sex from registry fields
    Rule checkerrulesEvaluates numeric criteria (labs, age) with no LLM
    Eligibility checkerlocal LLMJudges the remaining fuzzy criteria; answers must quote the note
    Criticlocal LLMRe-reads the note and challenges every exclusion
    ScorerrulesLabel, score and plain-language explanation

    Reading the results

    • ✓ Met: the note supports the criterion being satisfied (for exclusions: the patient does not have it).
    • ✕ Not met: the note contradicts it, with a quoted span as evidence.
    • ? Unknown: the note doesn't say. These are what a coordinator would check by hand.
